### Clips: проверить первым, но не обещать работу без настройки

Текущая документация подтверждает встроенную запись, загрузку локальных видео и импорт публичного Loom. Библиотека ищет по транскриптам, поддерживает папки и пространства. Это уже существенно ближе к задаче пользователя, чем отдельная транскрибация. [Функции Clips](https://raw.githubusercontent.com/BuilderIO/agent-native/main/packages/core/docs/content/template-clips-features.mdx).

Для внешнего агента предусмотрены JSON с метаданными и сегментами `startMs/endMs`, JPEG заданного момента и лист кадров диапазона. Частным записям можно выдать ограниченную ссылку на два часа. Наличие таких API не означает, что видео автоматически полностью проиндексировано по визуальному содержимому. Внутренний поиск документирован прежде всего по транскриптам. [Интеграции Clips](https://raw.githubusercontent.com/BuilderIO/agent-native/main/packages/core/docs/content/template-clips-integrations.mdx).

Agent Native автоматически предоставляет `/mcp` с теми же действиями приложения, Streamable HTTP и аутентификацией. Это подтверждение интеграционного механизма, а не проверка конкретной совместимости установленного у пользователя Codex с развёрнутым Clips. [MCP Server](https://raw.githubusercontent.com/BuilderIO/agent-native/main/packages/core/docs/content/mcp-protocol.mdx).

Для самостоятельного запуска нужны Node.js 22.22+ и pnpm. Локальный захват возможен до настройки остальных частей, но полный цикл требует хранилища и AI-кредитов: Builder.io либо отдельное S3-совместимое хранилище и провайдеры AI. [Руководство разработчика](https://raw.githubusercontent.com/BuilderIO/agent-native/main/packages/core/docs/content/template-clips-developers.mdx). Desktop — отдельный Tauri-клиент для macOS/Windows/Linux, которому всё равно нужен сервер Clips; сборка требует Rust/Tauri. Возможности нативного macOS захвата и распознавания нельзя автоматически переносить на Windows. [Desktop README](https://raw.githubusercontent.com/BuilderIO/agent-native/main/templates/clips/desktop/README.md).

Текущая документация описывает native распознавание → Builder-managed Gemini → Groq; анализ полного видео включается отдельно и требует Gemini. Личный Gemini API-ключ пользователя сам по себе не подтверждает готовность всей конфигурации. `.env.example` одновременно содержит Groq/OpenAI путь, поэтому точный актуальный путь BYOK следует проверять в выбранном релизе. Для рабочих материалов значимо и то, что документированный стандартный режим видимости новых записей — public, пока администратор его не изменил. [Функции Clips](https://raw.githubusercontent.com/BuilderIO/agent-native/main/packages/core/docs/content/template-clips-features.mdx), [пример конфигурации](https://raw.githubusercontent.com/BuilderIO/agent-native/main/templates/clips/.env.example).

Пост обещает понимание «вообще всего» в любой момент; подтверждены доступ к исходным кадрам и временным сегментам, а не такая полнота понимания. Автоматическую запись конкретного `meet.egovm.ru`, надёжный захват удалённого звука вместе с собственным микрофоном, длинные встречи и русскую точность нужно испытать отдельно. Браузерный старт записи требует действия пользователя. [Поведение агента](https://raw.githubusercontent.com/BuilderIO/agent-native/main/packages/core/docs/content/template-clips-agent.mdx).

Соседний шаблон **Brain** интересен как следующий слой: он принимает Clips/meeting/transcript источники, предоставляет гибридный поиск и ответы со ссылками. Это не доказательство полной мультимодальной индексации видеоряда; документация описывает прежде всего проверенные текстовые знания. [Brain README](https://raw.githubusercontent.com/BuilderIO/agent-native/main/templates/brain/README.md).

### claude-video / watch: быстрый пробный разбор одной записи

README прямо поддерживает локальный Codex, Claude Code и другие Agent Skills hosts. Локальный режим подготавливает временные кадры и транскрипт; Gemini-режим передаёт локальный файл Google Files API. Можно задать модель своим id. Выборка кадров имеет ограничения: balanced обычно до 100 кадров, efficient до 50; мелкие изменения кода могут пропасть при дедупликации. Авторы рекомендуют видео до десяти минут или выбранный интервал. Это полезно для проверки «может ли агент ответить по показанному экрану», но не заменяет архив и поиск по сотням встреч. Каталоги разборов считаются временными. Windows-команды установки есть, однако managed WhisperX физически проверен прежде всего на Apple Silicon. [README watch](https://github.com/bradautomates/claude-video).

### RAG-Anything: пригодный компонент, не готовый рекордер

В актуальном README явно появились видео: SceneDetect определяет сцены, VLM описывает ключевые кадры, faster-whisper транскрибирует аудиодорожку; результаты объединяются по времени. Можно импортировать подготовленный извне content-list. Следовательно, утверждение «этот проект только для PDF» сейчас неверно. Однако запись встреч, пользовательская медиатека, идентификация участников и MCP API не предоставляются автоматически данным pipeline. [README](https://github.com/HKUDS/RAG-Anything).

Метаданные пакета: Python >=3.10, beta, OS Independent; видео требует `raganything[video]`, FFmpeg, OpenCV, moviepy и faster-whisper. По умолчанию пакет подтягивает MinerU на Python 3.10—3.13; Python 3.14 и MinerU 4 имеют отдельные ограничения. [pyproject.toml](https://raw.githubusercontent.com/HKUDS/RAG-Anything/main/pyproject.toml). Проверенный upstream CI работает на Ubuntu с Python 3.10/3.11/3.12, а не на Windows. [workflow](https://raw.githubusercontent.com/HKUDS/RAG-Anything/main/.github/workflows/test.yaml). Разумный старт для пилота — отдельное Linux/WSL2/Docker-окружение Python 3.12; это архитектурный выбор, не подтверждённая установка на данном компьютере. В минимальном Linux нужны OpenCV системные библиотеки. В основном дереве проекта готовые Dockerfile/compose при проверке не обнаружены: контейнеризацию нельзя обещать одним готовым compose.

### Graphiti, zvec и OpenViking: различные дополнительные слои

Graphiti хранит временные факты и отношения; имеет MCP и поддержку Gemini, но требует графовой БД вроде Neo4j/FalkorDB. Он не записывает встречу и не восстанавливает отсутствующий видеоконтекст. В такой системе граф должен ссылаться на исходные временные доказательства; резюме и извлечённые отношения не заменяют оригинал. [Graphiti](https://github.com/getzep/graphiti).

zvec — встраиваемый индекс с плотными/разреженными векторами, полнотекстовым поиском и фильтрами. Текущий README содержит поддержку Windows и 64-битного Python 3.10—3.14. Он не получает смысл из MP4 сам: требуются извлечение текста/кадров, embeddings и модель ответа. [zvec](https://github.com/alibaba/zvec).

OpenViking организует знания, память и skills в виртуальной файловой системе `viking://` с краткими описаниями каталогов и навигацией агента. Это альтернатива слою контекста, не готовый сервис записи и точного видеоанализа. Слова канала об экономии токенов и «точности памяти» нельзя переносить на этот сценарий. [OpenViking](https://github.com/volcengine/OpenViking).

## Остальные подходящие публикации и причины не начинать с них

- **Cognee**, №2305, 27.12.2025: ещё один слой постоянной памяти/графа, возможная альтернатива Graphiti, не отдельный рекордер. [Репозиторий](https://github.com/topoteretes/cognee).
- **NotebookLM skill**, №2465 и №2572: проект сам описывает автоматизацию браузера через Patchright и ориентируется на local Claude Code. Это не официальный Google API, а ещё один зависимый от веб-интерфейса путь; не следует строить на нём единственное хранилище рабочих материалов. [Репозиторий](https://github.com/PleasePrompto/notebooklm-skill).
- **HyperBookLM**, №2202: в посте предложены URL/PDF/TXT, карты и сводки; этого недостаточно, чтобы подтвердить детальную временную видеопамять. [Ссылка из поста](https://github.com/hyperbrowserai/hyperbooklm).
- **LLM Wiki**, №2938: полезный паттерн страниц сущностей, противоречий и синтеза, но не готовый продукт. Пересказ канала «RAG сломан» не является техническим доказательством отказа от поиска. [Первоисточник из поста](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f).
- **Obsidian + Claude PKM**, №2283 и №2859: удобный читаемый агентами слой Markdown, но видео/OCR/временные ссылки надо создать отдельно. [Шаблон](https://github.com/ballred/obsidian-claude-pkm/).
- **Rowboat**, №2957: описание поста «локальный Cowork с vault» расходится с текущим позиционированием README: теперь это пространства для совместной работы людей и агентов. Нельзя выбирать актуальный продукт по одному старому посту. [Текущий репозиторий](https://github.com/rowboatlabs/rowboat).
- **FastAPI-MCP**, №1504: потенциальная обёртка уже имеющегося Python API, но не создаёт нужных операций поиска/кадров/доказательств сама. [Ссылка из поста](https://github.com/tadata-org/fastapi_mcp).
- **OCR/конвертеры**: Docling №1845, MarkItDown №1966, PaddleOCR №1924, MinerU №3375 полезны для файлов/кадров. Они не понимают автоматически динамику демонстрации и произнесённый контекст.
- **Claude Meetings**, №4326: сам пост ограничивает старт Google Meet и Team/Enterprise, поэтому из него не следует совместимость с `meet.egovm.ru` и имеющимися подписками. Заявление не проверялось как отдельный продукт.

## Вывод для дальнейшего решения

Первая проверка готового решения — **Clips** на одной разрешённой к облачной обработке записи с русской речью и демонстрацией экрана. Обязательны вопросы к видеоряду, поиск по двум встречам и переход к исходному таймкоду; одно красивое summary не считается успехом.

Самый быстрый эксперимент с уже имеющимися ресурсами — **watch в Codex** на коротком фрагменте через существующий Gemini-ключ либо с локально подготовленными данными. Это проверит мультимодальную пользу, но не задачу долговременного архива.

Если готовое решение не пройдёт критерии, собственную систему разумно собирать из существующего Video-Transcribe, извлечения кадров/OCR, Gemini/VLM, долговечного хранилища доказательств и индекса; **RAG-Anything** заслуживает пилота как готовая часть обработки. Graphiti/OpenViking добавлять только после подтверждения, что простой поиск с фильтрами и таймкодами не решает реальные вопросы.
