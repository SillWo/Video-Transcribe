# Реализация архива встреч

Дата начала: 14 ноября 2026 года. Исходные исследования и пользовательские документы сохранены. Этот документ дополняет FINAL-ARCHITECTURE.md; решения ниже имеют приоритет над её первой редакцией.

## Уточнения согласованной архитектуры

- Записывается **выбранный монитор целиком**, включая переключение из браузера в Jira, DBeaver и другие приложения. OBS управляется локально через obs-websocket. Микрофон и звук браузера — отдельные дорожки. Перед стартом нужны изображение выбранного монитора и живые уровни обоих источников.
- Для совместимости имеющегося ASR, который извлекает первую аудиодорожку, запись предусматривает три дорожки: общая смесь, только браузер, только микрофон. Первая используется для общей расшифровки, две отдельные сохраняются с ролями и временными смещениями. Это не обещает отдельных дорожек всех удалённых участников. Импорт чужих многодорожечных файлов требует определения состава звука; отсутствие такой информации обозначается явно.
- Импорт существующих видео входит в первую версию. После импорта обработка запускается только по явной команде пользователя. Исходный профиль — Parakeet; Qwen и Whisper сохраняются.
- Сначала допустимо локальное хранение оригиналов. Google Drive — подключаемое хранилище оригиналов и резервных копий, а не обязательное условие локальной работы.
- Поиск: SQLite FTS5, буквальный поиск рабочих идентификаторов и локальные многоязычные эмбеддинги. Отдельные zvec, векторная БД и граф не вводятся без измеренной необходимости.
- Компактный локальный архив сохраняется минимум полгода. Срок оригиналов — 30 дней; автоматическая очистка выключена. Для удаления нужны проверенный готовый архив конкретной встречи и подтверждённая резервная копия. Испытания удаления выполняются только на тестовых копиях.
- MCP по STDIO предоставляет только чтение. Получение изображения проверяется реальным вызовом в Codex; путь к JPEG и успешная регистрация сервера не считаются такой проверкой. Закрытое окно приложения не мешает чтению и не запускает запись или очередь.
- Ответы опираются прежде всего на встречи. Агент различает речь, экран и собственный вывод, проверяет последовательный контекст и более поздние решения. Дополнительные рабочие/публичные источники обозначаются отдельно; внутренние данные не входят в публичные поисковые запросы.
- После отдельного grilling согласованы режимы «Авто» и «Вручную» для CPU/GPU, выбор по реальным замерам скорости/качества, приоритет созвона и остановка очереди при ошибке без автоматического fallback. Полное решение: [HARDWARE-EXECUTION.md](HARDWARE-EXECUTION.md). Оно имеет приоритет над старыми предложениями автоматического повтора на CPU.

## Порядок работ и приёмка

1. Переносимый архив: постоянный ID, исходная речь и отдельные редакторские правки, подтверждённые имена, экранные события, звук, манифест и Markdown.
2. Узкий сквозной путь на учебном видео: импорт → имеющийся ASR → изменения небольших областей/OCR → архив → индекс → чтение и настоящее изображение через MCP → открываемое доказательство.
3. Интеграция с постоянной очередью и React/Electron: выбор встреч для обработки, повтор этапа, восстановление, редактирование, словарь и подключения без терминала в ежедневной работе.
4. OBS: выбор монитора и браузерного источника, предварительный просмотр, уровни, отдельные дорожки, заметная запись и автоматический импорт результата.
5. Хранение и восстановление: выбор каталога, проверенные копии, пересоздание индекса, защита очистки, сохранённые доказательства после удаления тестового оригинала.
6. Приёмка: одинаковые 2–3 рабочие записи и заранее зафиксированные 10 вопросов, минимум 9 правильных ответов, ни одной выдуманной цитаты. Замер двухчасовой записи на Ryzen 7 8845H/Radeon 780M, включая все этапы; затем фактическая неделя для оценки очереди и объёма.

Для каждого этапа отдельно фиксируется, что проверено программными тестами, учебным примером, реальным клиентом Codex и рабочими встречами. Учебные данные не подменяют пилот качества или двухчасовой замер.

## Найденная среда

- Существуют Electron/React, FastAPI, SQLite-история и постоянная очередь, адаптеры Parakeet/Qwen/Whisper и диаризация Nemotron.
- На целевом компьютере обнаружен Ryzen 7 8845H. Основная среда проекта использует Python 3.13.6, несмотря на Python 3.12 в исходном плане.
- Старый пакет rapidocr-onnxruntime 1.4 несовместим с Python 3.13. Для реализации выбран современный RapidOCR с ONNX Runtime и кириллической моделью. Совместимость и качество проверяются отдельно.
- Регистрация Codex выполняется штатной командой управления MCP. Состояния «зарегистрирован», «проверен протокол» и «клиент действительно получил изображение» различаются. Официальное основание: [MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
