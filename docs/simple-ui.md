# Новый интерфейс

Интерфейс открывается по адресу `/` в Windows. Вкладка **«Транскрибация»** принимает ссылку или путь к файлу, а вкладка **«История»** показывает все сохранённые задачи, включая ожидающие, выполняющиеся, завершённые, ошибочные и прерванные. Неизвестные адреса и старый маршрут `/models` перенаправляются на главную страницу. Этот системный диалог и GPU-подготовка текущего UI не поддерживаются на Linux.

## Рабочий сценарий

- Вставьте HTTP(S)-ссылку или выберите файл кнопкой **«Выбрать файл»**. Системный диалог Windows открывает дочерний процесс Python через стандартный Tk (Tcl/Tk), поставляемый с Python для Windows. Это не загрузка через HTML-поле браузера и не PowerShell Forms.
- Профили **«Качество»**, **«Баланс»** и **«Экономный»** используют соответственно `large-v3`, `large-v3-turbo` и `small`. Это названия моделей проекта, в форме они не показываются. Все профили доступны на CPU.
- Устройство по умолчанию — доступный GPU, иначе CPU. При выборе CPU можно задать число потоков в пределах числа логических процессоров. По умолчанию используются все логические потоки.
- Пунктуация включена по умолчанию. Обработка пунктуации предназначена для русской речи; интерфейс показывает уведомление, когда backend обнаруживает другой язык.
- Обычный запуск готовит зависимости приложения и GPU-runtime, не проверяя наличие весов каждого профиля. При создании задачи интерфейс автоматически подготавливает выбранную модель и, если пунктуация включена, её веса. `start.ps1 -SetupOnly` остаётся вариантом предварительной подготовки всех профилей и весов пунктуации; `start.ps1 -CheckOnly` проверяет готовность обычного запуска, а `start.ps1 -CheckOnly -SetupOnly` дополнительно проверяет все веса без загрузки.
- Во время задачи интерфейс показывает шесть этапов: подготовка модели, получение записи, подготовка аудио, распознавание речи, пунктуация и готовый результат. Проценты и объём/длительность показываются только когда backend присылает соответствующие измерения; неизвестный процент отображается как неопределённый прогресс без оценки оставшегося времени. Для текущего этапа показывается его фактическая длительность. Если во время получения данных обновления долго не приходят, интерфейс сообщает об ожидании и показывает отдельное предупреждение при сбое опроса.
- Во время ожидания и обработки доступна кнопка **«Отмена»**. После подтверждения backend показывает **«Отменена»**; пока сервер завершает остановку, отображается **«Отменяется»**. Отмена сохраняет исходный файл и кэш моделей. Отменённую задачу можно повторить или создать новую с текущим источником и настройками. Если текущий запуск приложения не поддерживает отмену, интерфейс сообщает об этом и продолжает показывать реальное состояние задачи.
- Пока задача выполняется или отменяется, повторный запуск блокируется. При ошибке или прерывании можно явно нажать **«Повторить попытку»**: создаётся новая запись истории с текущими источником и настройками. Автоматических повторных запусков нет.
- Завершённый текст можно править. Изменения отправляются на сервер с debounce и упорядоченной записью, версия защищает от перезаписи внешних правок. Ошибка конфликта оставляет черновик на экране и требует скопировать его до обновления страницы.
- Копирование, скачивание и переход между вкладками сначала ожидают сохранения последнего черновика. Если сохранить не удалось, действие отменяется и показывается ошибка.
- История содержит источник, дату, статус и ссылки на TXT/MD без текста внутри списка. Удаление требует подтверждения, не работает для активной или отменяющейся задачи и удаляет её артефакты. Исходный файл пользователя не затрагивается.

## Проверенные сценарии

В UI проверены оба типа источника: локальный файл и публичное видео `jfk.en` из репозитория Whisper на GitHub. На AMD Radeon 780M проверен Vulkan с профилем **«Баланс»** (модель `large-v3-turbo`) для русской речи с пунктуацией; отдельно прошёл реальный CPU-прогон профиля **«Баланс»** для русской речи с пунктуацией. Для английского `jfk.en` интерфейс показал уведомление, что русская пунктуация не применяется. Быстрое редактирование, копирование совпадающего текста и загрузка MD проверены; файлы каждой задачи сохраняются и остаются доступными из истории.

CUDA проверялась только mock-тестами: теста на физической NVIDIA-видеокарте не было. В API-проверках активная задача блокировала удаление и второй запуск (ответ `409`); удаление старой тестовой записи вернуло `204` и сохранило исходное видео, кэш моделей и результаты других задач. `start.ps1` по-прежнему подготавливает все модели и веса пунктуации при установке или повторной подготовке. Если выбранной модели или весов пунктуации нет, приложение автоматически подготовит их при запуске задачи и продолжит обработку. Автоматическая загрузка отсутствующих весов на реальном сетевом сценарии отдельно не проверялась.

API-тесты отмены проверяют переход задачи в состояние отмены, блокировку удаления активной задачи и сохранность исходного файла и кэша моделей. Это проверка API, а не отдельный прогон отмены на физическом GPU-оборудовании.

## Хранение и ограничения

Настройки интерфейса хранятся в `localStorage`. Тексты расшифровок в браузерное хранилище не записываются: история и результаты сохраняются на backend в `.runtime/history.sqlite3` и `.runtime/transcriptions/`. Последняя задача восстанавливается после перезагрузки; если приложение закрыто во время обработки, backend помечает её как прерванную.

Интерфейс рассчитан на настольное окно шириной от 1024 пикселей. Длинные пути и источники в заголовке задачи сокращаются, полный источник доступен при наведении; таблица истории показывает источники в пределах своей ячейки. Форматы результата — TXT и MD. Настройки модели, языка, временных меток и извлечённого аудио в этом интерфейсе не представлены. Для автоматической подготовки отсутствующих весов требуется сеть; если загрузка не удалась, задача показывает ошибку и её можно повторить после восстановления соединения.
