# Настольное приложение

Обычный запуск `start.ps1` подготавливает backend, production UI и закреплённый Electron, затем открывает окно Video Transcribe. Страница работает локально внутри приложения; отдельный браузер запускать не нужно. Окно имеет стандартную рамку Windows. Кнопка закрытия прячет приложение в область уведомлений, а пункты **«Открыть»** и **«Выход»** доступны из значка в трее. Повторный запуск показывает уже открытое окно.

Перед выходом приложение проверяет очередь. Если задачи выполняются или ожидают, можно подтвердить выход: текущая обработка штатно остановится, а ожидающие задачи останутся в FIFO-очереди. Если остановка не подтверждена или черновик не сохранён, приложение остаётся открытым.

## Работа с задачами

- Для URL вставьте ссылку; для файлов нажмите **«Добавить файлы»**. Системный диалог Windows позволяет выбрать несколько файлов, а в настольном приложении файлы можно перетащить в область добавления. В обычном браузере перетаскивание не поддерживается: используйте **«Добавить файлы»**. Перед добавлением можно просмотреть выбранные имена и убрать отдельные строки. Папки и элементы без обычного локального пути отклоняются.
- Каждый файл из списка создаётся как отдельная задача. Повторяющиеся пути разрешены и создают отдельные задачи. Одно нажатие **«Добавить в очередь»** отправляет текущий список файлов с одинаковым снимком профиля, устройства, числа потоков CPU и настройки пунктуации. Уже добавленные задачи сохраняют эти значения; для следующей порции настройте параметры и добавьте новый список.
- Профили **«Качество»**, **«Баланс»** и **«Экономный»** соответствуют моделям проекта; доступны CPU и подходящее GPU. Настройки распознавания сохраняются в настройках интерфейса.
- Очередь обрабатывает задачи по одной, в порядке поступления. Для активной и ожидающих задач показываются отдельные вкладки в рабочем пространстве. Ожидающую задачу можно отменить; команда **«Отменить всё»** останавливает активную обработку и очищает очередь. Активная задача показывает этап и затраченное время; оценка оставшегося времени не отображается.
- При ошибке, прерывании или отмене кнопка **«Повторить попытку»** создаёт новую задачу с теми же источником и сохранёнными настройками исходной задачи. Изменения текущих настроек формы на повтор не влияют.
- Навигационные вкладки **«Транскрибация»** и **«История»** разделяют рабочее пространство и список всех задач. Закрытие вкладки отдельной задачи убирает её из рабочего пространства, но не удаляет её запись или результаты из истории. Удаление в **«Истории»** — отдельное действие с подтверждением.
- Текущий результат можно редактировать. Автосохранение использует локальный обработчик; переходы между задачами, разделами и выгрузка результата ожидают завершения сохранения черновика.
- Перезапуск или выход сохраняет историю и ожидающие задачи в `.runtime/history.sqlite3` и `.runtime/transcriptions/`; исходные медиафайлы остаются по исходным путям. Выход штатно прерывает текущую обработку, ожидающие остаются в очереди.

## Подготовка и команды

Первый `start.ps1` может установить Python для текущего пользователя, подготовить `.venv`, FFmpeg, модели/графические runtime, собрать UI и установить Electron 45.2.3. Electron-кэш, npm-кэш, Python-кэш, логи, временные файлы, профиль приложения и данные пользователя располагаются внутри `.runtime` проекта. Установка не создаёт автозапуск Windows и не собирает EXE-инсталлятор.

```powershell
.\start.ps1                      # подготовить окружение и открыть desktop-приложение
.\start.ps1 -SetupOnly           # подготовить зависимости и модели, не открывая приложение
.\start.ps1 -CheckOnly           # проверить обычный запуск, включая desktop-зависимости
.\start.ps1 -CheckOnly -NoBrowser # проверить headless/backend-окружение без Electron
.\start.ps1 -NoBrowser           # запустить только backend без окна
.\start.ps1 -Stop                # штатно остановить host, сохранив очередь
```

Host по умолчанию слушает `127.0.0.1:8000`. Для отдельной QA-среды можно задать `VT_SIMPLE_RUNTIME_DIR` и запускать `python -m services.app_host --host 127.0.0.1 --port 8003`; runtime-каталог изолирует и профиль host. Логи находятся в `.runtime/logs`. Старые задачи и история остаются на месте при остановке и повторном запуске.
