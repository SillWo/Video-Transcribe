# Проверка очереди и desktop-оболочки

## Проверено

- Прошли 189 Python unit tests, 7 проверок UI-гонок, production build и lint. `start.ps1` прошёл PowerShell AST-проверку, обычный `-CheckOnly` и `-CheckOnly -NoBrowser`.
- Обычный `start.ps1` запустил desktop-приложение с новым локальным host на `127.0.0.1:8000`.
- На CPU и AMD Radeon 780M через Vulkan обработаны русская WebM-запись и английский FLAC. Язык определялся отдельно для каждого файла; русская пунктуация применялась только к русской записи. Проверены добавление задач в FIFO, продолжение очереди после повреждённого файла, отмена ожидающей задачи, активной задачи и всей очереди.
- Проверены штатный выход с остановкой активной задачи и сохранением ожидающих, отказ выхода при ошибке сохранения черновика, а также перезапуск с восстановлением ожидающих задач в приостановленной очереди. Отдельно проверено аварийное завершение host: его принадлежащие процессам host дочерние процессы завершились, сторонний процесс остался работать.
- В реальном Electron 45 проверены загрузка локально обслуживаемого UI, bridge выбора файлов, файлово-привязанные элементы через `DataTransfer`, сохранение исходных Unicode-путей и повторяющихся путей без копирования. Непривязанный JS `File` отклоняется. Проверены записи из системного буфера обмена, выгрузка TXT/MD и независимое сохранение черновиков нескольких задач.
- Проверены размеры окна 1366×768, 1093×614 и 1024×768; редактор сохраняет минимальную высоту 138 px.

## Заглушки и непроверенные устройства

- Контракт системного выбора файлов проверялся через заглушку системного диалога. Физический щелчок по диалогу Windows и перетаскивание мышью из Проводника не проверялись. `DataTransfer` использовал настоящие файлово-привязанные элементы внутри Electron, но не физический жест Проводника.
- NVIDIA CUDA проверялась mock-тестами; физической NVIDIA-видеокарты для прогона не было.

Во время интеграции managed-host дочерние процессы Python наследовали stdin host и могли зависать при запуске. Host теперь запускает принадлежащие ему дочерние процессы с `stdin=DEVNULL`; регрессионная проверка запуска прошла.
