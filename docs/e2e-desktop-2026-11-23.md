# Проверка Video Transcribe перед публикацией · 23 ноября 2026

**Решение на момент проверки — отложить публикацию.** В реальном окне Windows первая расшифровка завершилась, после чего приложение перестало сохранять правку и принимать следующую задачу. На чистом профиле также воспроизвелись ошибки подготовки Python и OBS. Ниже приведены способы воспроизведения и результаты повторных проверок.

## Что проверяли

Согласованный способ распространения — исходники и `start.ps1` под Windows. Проверялась рабочая копия поверх `ee9d7f4` с незакоммиченными изменениями. В локальном `origin/main` на момент прогона нет части модулей проверяемой версии, включая `services/archive_api.py` и `ui/src/pages/ArchivePage.tsx`. Результаты относятся именно к рабочей копии. Сборка Setup.exe из отдельной ветки находится за пределами согласованной приёмки.

ОС — Windows 11, сборка 26200. Рабочее окружение — Python 3.13.6, Node.js 24.14.0, AMD Radeon 780M. Для имитации нового пользователя запускали копию исходников без `.venv`, `node_modules` и проектного кэша. На компьютере уже были установлены Git, Python, Node.js и FFmpeg. Чистая операционная система с установкой этих программ через winget в этот прогон не входила.

GPT-6 Luna со средним уровнем рассуждения управляла отдельным окном Electron через «Компьютер». У него были собственные история, словарь, настройки, пользовательские данные Electron и архив. Родительский агент отдельно проверял работающий HTTP-сервис, взаимодействие по MCP stdio, файлы экспорта и восстановленную копию. Локальная папка доказательств — `.runtime/e2e-release-20261123/`. Она содержит технические данные и не предназначена для распространения вместе с отчётом.

## Что увидел пользователь и почему

| Сценарий воспроизведения | Действие и наблюдение | Причина и проверка |
|---|---|---|
| Первый запуск в Windows PowerShell 5.1 | Запустить `start.ps1` на ПК с Python 3.13 и без 3.12. Появилось `No suitable Python runtime found`. Скрипт завершился до создания окружения. | `Select-Python` пробовала `py -3.12`. При `$ErrorActionPreference = 'Stop'` PowerShell превращал stderr launcher в исключение, поэтому до работающего `py -3` управление не доходило. После исправления тот же запуск создал окружение, установил основные зависимости и прошёл `pip check`. |
| Следующий шаг чистой установки | После сообщения `No broken requirements found` появился `Traceback (most recent call last)`. Окно приложения не открылось. | Пробный импорт `razdel` в `Test-PostprocessPackages` происходит до установки пакетов пунктуации. В свежем окружении импорт завершился `ModuleNotFoundError`. Windows PowerShell прервал проверку на stderr. После исправления скрипт установил пунктуацию, собрал интерфейс и запустил Electron. Стартовая страница вернула HTTP 200, `/api/health` ответил, а штатный `start.ps1 -CheckOnly` подтвердил готовность окружения. |
| Первая подготовка записи | На экране «Запись» нажать «Подготовить». Диалог «Запись недоступна» показал `HTTP Error 404: Not Found`; выбрать источники было невозможно. | В URL закреплённого OBS 33.0.1 отсутствовал суффикс `-x64`. Старый URL вернул 404, правильный — 200. После исправления загрузчик с нуля получил 223 786 669 байт, проверил закреплённый SHA-256 и извлёк `obs64.exe`. |
| Первая публикация WAV в Electron | Запустить `russian.wav` на Whisper small/CPU, дождаться «Готово», изменить последнее слово, перейти в архив или добавить FLAC. На несколько минут остались «Сохраняем…» и «Добавляем…». Нажатия на разделы перестали менять экран. После остановки тестового процесса в файле остался исходный текст. | Процесс backend был жив, но запрос к `/api/health` перестал проходить. Снимок потоков показал импорт нативного NumPy в индексаторе. Windows связала его ожидание с потоком наблюдения за Electron, заблокированным в `os.read(0, 1)`. В минимальном дочернем процессе с открытым stdin-каналом блокирующий watcher воспроизвёл зависание. При опросе готовности Windows pipe через `PeekNamedPipe` импорт завершился при всё ещё открытом канале. В отдельном headless-экземпляре тот же WAV прошёл индексацию и редактирование. |

Whisper small исказил окончание фразы в русском примере. Копирование исходного результата дало уведомление «Текст скопирован». Ошибка распознавания и потеря неподтверждённой правки — разные наблюдения. Качество модели на других голосах, языках и шумных записях по этому примеру оценить нельзя.

**Повтор правки в исправленном Electron.** Luna открыла ту же карточку, исправила слово на «видеокарты», дождалась «Сохранено» и увидела уведомление словаря. После перехода в настройки и повторного открытия карточки текст сохранился. Сервер вернул ревизию 1. Из того же окна Luna отправила WebM на обработку, и сервер опубликовал карточку видео.

**Неверная причина отказа для входного файла.** 52-байтный текстовый файл и корректный WAV размером 256 078 байт с восемью секундами цифровой тишины получали одно сообщение «Файл пустой». Проверка структуры и проверка амплитуды сводили разные исходы к одному коду. После исправления повторная пакетная отправка выдала три разных результата: `media_empty` для файла на 0 байт, `media_format_unsupported` для текста и `audio_silent` для полностью тихого WAV. Последнее сообщение объясняет, что дорожка декодирована и для расшифровки нужен записанный звук.

**Архив зависал во время установки OBS.** После нажатия «Подготовить» кнопка стала недоступной, сохранив прежнюю подпись. При переходе в другую задачу появилось «Открываем…», а в архиве оставались счётчик 0 и «Загружаем архив», хотя там уже были результаты. Снимок потоков выявил 39 обработчиков запросов статуса, ожидавших блокировку рекордера, и один обработчик загрузки OBS, удерживавший её. Все 40 рабочих потоков оказались заняты. Независимые запросы к `/api/health` и `/api/archive` превысили двухсекундный таймаут. На экране подготовки добавлены явный индикатор, подпись «Подготавливаем OBS…» и пояснение о первой загрузке.

Исправленный обработчик отдаёт состояние подготовки, пока рекордер занят установкой. В отдельном интеграционном прогоне загрузчик задержали на 16 секунд. За это время Edge показал индикатор и открыл архив. Три серии запросов статуса, здоровья сервиса и архива завершились за 92, 32 и 25 мс. Это измерение отзывчивости во время контролируемой задержки. Размер и SHA-256 настоящей загрузки проверялись отдельно.

**Первая задача после установки из исходников.** В новом окружении без проектного кэша приложение загрузило веса Whisper small и русской пунктуации. Русский WAV обработан на CPU за 436 секунд вместе с первоначальной подготовкой. Стадия пунктуации завершилась, в архиве появился текст из 135 символов. Этот прогон проверяет обычную команду запуска на Windows с уже установленными системными инструментами.

В дополнительном HTTP-прогоне публичная ссылка на WAV завершилась успешно, а для локального адреса приложение вернуло HTTP 400 с пояснением о публичном сайте. Видео без звуковой дорожки опубликовалось с пометкой о недоступности речи. Страницы списка аудио не дублировали первую запись, попытка перезаписать устаревшую ревизию вернула HTTP 409 и сохранила первую правку. Удаление тестовой карточки дало HTTP 404 при повторном открытии, SHA-256 исходного WAV остался прежним.

Новый клиент открыл именно восстановленную папку и прочитал обе карточки. Текст аудио совпал с контрольным экспортом, а для видео клиент получил кадр в виде изображения. Ожидающая задача была успешно отменена отдельно от других элементов пакета.

При штатной остановке отдельного host с активной задачей и двумя ожидающими активная перешла в `interrupted`. После перезапуска обе ожидающие сохранились в исходном порядке. Очередь показала причину `recovered_pending` и продолжилась по команде пользователя. Через интерфейс архива в Edge сохранены на диск TXT и MD с новой контрольной правкой. После перезагрузки страницы редактор содержал тот же текст.

Luna отдельно выбрала WAV и FLAC одним системным диалогом, увидела их двумя строками, отменила ожидающий FLAC и повторила задачу из вкладки. Повтор завершился. Публичная ссылка на речь Кеннеди из того же интерфейса дошла до «Готово» и дала узнаваемую английскую фразу. Для английского языка интерфейс объяснил пропуск русской пунктуации. Локальный URL привёл к сообщению о необходимости публичного сайта.

## Автоматические проверки

Production-сборка React/TypeScript прошла. В исходном прогоне прошли 82 теста UI, 4 теста Electron и 734 теста Python с 43 subtests. Два Python-теста пропущены, поскольку Windows не разрешила создавать символьные ссылки на каталоги. ESLint завершился с кодом 0. Для исправления загрузчика OBS отдельно прошли все 22 теста рекордера. Полный набор до исправлений был зелёным и не выявил зависания при реальном взаимодействии Electron и backend.

После изменений в launcher и managed host прошли 737 тестов Python с теми же двумя пропусками и 43 subtests. Новый тест Windows держит родительский stdin открытым во время импорта NumPy, затем закрывает его и проверяет завершение наблюдателя.

Следующий полный прогон выявил гонку в тесте просмотра материалов. На Windows клиент уже прочитал ответ HTTP 206, когда тест попытался удалить файл, ещё открытый потоком выдачи последних байтов. Тест теперь проверяет HTTP 404 для отсутствующего пути и отсутствующего источника после проверки диапазона. После исправления проверка прошла пять раз подряд, весь модуль MCP — 32 теста. С учётом новых проверок сообщений для медиафайлов и статуса OBS итоговый прогон дал **743 прошедших теста Python, 2 пропуска и 43 subtests**.
