## Описание проекта

`Video Transcribe` — это локальный сервис для преобразования речи из аудио- и видеоисточников в текст без привязки к облачному SaaS-сценарию.

Сервис поддерживает два основных типа входных данных:
- локальные файлы, загружаемые с компьютера пользователя;
- удалённые ссылки на медиаресурсы, которые может обработать `yt-dlp`.

Проект включает:
- backend API на `FastAPI`;
- локальный web UI на `React + Vite`;
- пайплайн извлечения аудио через `ffmpeg`;
- распознавание речи через `faster-whisper`;
- для русского языка опциональную постобработку текста по цепочке `faster-whisper -> восстановление пунктуации -> финальная шлифовка предложений`.

Для legacy API/CLI-сценариев доступна отдельная предварительная проверка удалённого источника: она показывает, поддерживается ли ссылка и пригоден ли источник для извлечения аудио. Новый упрощённый UI запускает расшифровку напрямую.

## Новый интерфейс

Основной интерфейс предназначен для простого рабочего сценария: вставьте ссылку на видео или выберите локальный файл, укажите профиль распознавания и нажмите **«Расшифровать»**. Системное окно Windows запускается дочерним процессом Python с обычным Tk (Tcl/Tk), поставляемым с Python для Windows; HTML-загрузка браузера и PowerShell Forms не используются. Полный путь выбранного файла показывается в форме. Для AMD Radeon 780M и других поддерживаемых графических устройств пункт **«Видеокарта»** доступен, когда графический runtime готов; иначе интерфейс предлагает использовать процессор.

Профили имеют фиксированное соответствие моделям: **«Качество» — `large-v3`**, **«Баланс» — `large-v3-turbo`**, **«Экономный» — `small`**. Все три профиля работают на CPU, включая процессоры AMD. По умолчанию используется доступный GPU, иначе CPU; для CPU выбираются все логические потоки. Пунктуация включена по умолчанию и применяется к русской речи. Обычный запуск `start.ps1` готовит зависимости и GPU-runtime, но не требует наличия весов всех профилей. Если выбранной модели или весов пунктуации нет, приложение само подготовит их во время запуска задачи и продолжит обработку. Для загрузки требуется сеть. Команда `start.ps1 -SetupOnly` по-прежнему может заранее скачать все профили и веса русской пунктуации.

После завершения текст можно редактировать прямо в большом поле результата. Изменения автоматически сохраняются на компьютере; также доступны копирование текста и загрузка TXT или MD. Страница **«История»** показывает прошлые задачи, дату, статус и ссылки на файлы. Она не хранит текст расшифровки в браузере. Удаление записи из истории также удаляет её файлы результата; исходные пользовательские файлы и загруженные медиаресурсы при этом не удаляются. Данные истории и результаты размещаются в `.runtime/transcriptions/`, индекс истории — в `.runtime/history.sqlite3`.

Расширенные команды и старые CLI-инструкции проекта остаются доступны и не требуют использования нового интерфейса.

В проверенном UI-сценарии использовались локальный файл и публичный `jfk.en` из репозитория Whisper на GitHub. На AMD Radeon 780M проверены Vulkan, профиль **«Баланс»** и русская пунктуация; отдельно прошёл реальный CPU-прогон этого профиля для русской речи. Для английского примера интерфейс показал уведомление о неприменении русской постобработки. Также проверены редактирование, копирование совпадающего текста, загрузка MD и сохранность файлов задачи в истории. NVIDIA CUDA проверялась только mock-тестами; физическая видеокарта NVIDIA не тестировалась. Фактическая автоматическая загрузка отсутствующих весов и работа с неподдерживаемым оборудованием отдельно не проверялись.

## Описание функционала

- Расшифровка локальных аудио- и видеофайлов.
- Расшифровка удалённых медиаисточников по URL через `yt-dlp`.
- Для legacy API/CLI доступна отдельная проверка ссылки перед транскрибацией.
- В новом интерфейсе доступны результаты `txt` и `md`, редактирование и история задач.
- Интерфейс показывает шесть этапов обработки, текущую длительность и доступный от backend прогресс. Если процент неизвестен, показывается неопределённый индикатор; оценка оставшегося времени не рассчитывается. При ошибке или прерывании пользователь может явно повторить задачу с текущими источником и настройками.
- Активную задачу можно отменить из панели прогресса; интерфейс отображает подтверждённый статус отмены и оставляет исходный файл и кэш моделей нетронутыми.
- Поддерживаются CPU и доступное системное GPU-устройство.
- Опциональное сохранение промежуточного извлечённого аудио.
- UI включает восстановление русской пунктуации по умолчанию; в legacy CLI post-processing можно включить отдельно через `kontur-ai/sbert_punc_case_ru` и `razdel`.

## Пример пользовательского сценария при работе с удалёнными ссылками

1. Откройте вкладку **«Транскрибация»** и вставьте URL видео.
2. Выберите профиль и устройство; для обычного случая можно оставить значения по умолчанию.
3. Нажмите **«Расшифровать»** и дождитесь статуса **«Готово»**.
4. При необходимости отредактируйте текст; изменения сохраняются автоматически.
5. Скопируйте результат или скачайте TXT/MD. Предыдущие задачи доступны во вкладке **«История»**.

## Пример пользовательского сценария при работе с локальным файлом

1. Откройте вкладку **«Транскрибация»** и выберите **«С компьютера»**.
2. Нажмите **«Выбрать файл»**: откроется системное окно Windows, а полный путь появится рядом с кнопкой.
3. Укажите профиль и устройство, затем нажмите **«Расшифровать»**.
4. Отредактируйте распознанный текст и скачайте его в TXT или MD. Исходный файл на компьютере не изменяется.

## Гайд на установку под Windows

### Первый запуск

1. Установите Git, клонируйте репозиторий и откройте его папку в Проводнике.
2. Откройте PowerShell в папке проекта и запустите `.\start.ps1`. При необходимости скрипт установит Python 3.12, Git и Git LFS через `winget` для текущего пользователя, создаст `.venv`, поставит основные пакеты, соберёт production UI и подготовит локальные GPU-runtime в `.runtime`. Веса выбранного профиля и пунктуации приложение загрузит при первом задании. Для предварительной загрузки всех моделей и пунктуации используйте `start.ps1 -SetupOnly`.
3. Скрипт откроет `http://127.0.0.1:8000`, когда backend сообщит о готовности.

Если политика PowerShell блокирует запуск локального файла, используйте одноразовый вызов, который не меняет системную политику:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

Установка выполняется без прав администратора и не меняет системный PATH. Node.js 22 LTS загружается из официального архива с проверкой SHA-256. `ffmpeg` и `ffprobe` устанавливаются через пакет `Gyan.FFmpeg.Shared`; если `winget` недоступен, поставьте Python 3.12+, Node.js 20.19+ или 22.12+ и FFmpeg вручную и убедитесь, что `python`, `node`, `npm`, `ffmpeg` и `ffprobe` доступны текущему пользователю. Перезапустите `.\start.ps1` после ручной установки.

Кэш Python-пакетов, временные файлы и модели для этого запуска направляются в `.runtime` внутри папки проекта. Поэтому скачанные модели остаются на том же диске, где расположен проект; прежние пользовательские кэши скрипт не переносит и не удаляет.

Полезные команды из терминала в папке проекта:

```powershell
.\start.ps1 -CheckOnly       # проверить обычный запуск без установки и загрузки моделей
.\start.ps1 -CheckOnly -SetupOnly # проверить также наличие всех моделей и весов пунктуации
.\start.ps1 -SetupOnly       # подготовить зависимости, все модели и интерфейс без запуска
.\start.ps1 -SkipPostprocess # пропустить установку пакетов и весов русской пунктуации
.\start.ps1 -InstallPostprocess # явно включить русскую постобработку (это значение по умолчанию)
.\start.ps1 -NoBrowser      # запустить backend без открытия браузера
.\start.ps1 -Stop            # остановить только backend, запущенный этим проектом
```

Пакеты русской постобработки устанавливаются при подготовке проекта из `requirements-postprocess.txt`; её веса загружаются автоматически при первом задании с включённой пунктуацией или заранее командой `start.ps1 -SetupOnly`. Скрипт ставит Git и Git LFS, если они отсутствуют. Если Git или Git LFS нельзя установить через `winget`, поставьте их для текущего пользователя вручную. Логи запуска backend находятся в `.runtime\logs`.

Для AMD GPU используется подготовленный whisper.cpp Vulkan runtime и GGML-модель. Для NVIDIA интерфейс использует локально установленный CUDA runtime с CUDA 12 и cuDNN 9; совместимый NVIDIA-драйвер должен быть установлен пользователем. Установщик подготавливает runtime-библиотеки, но не устанавливает системный драйвер. Если выбранный GPU недоступен или несовместим, приложение сообщает об ошибке и не переключается скрытно на CPU.

## Legacy: backend/CLI под Linux

Этот раздел описывает только старый backend/CLI-сценарий. Новый упрощённый интерфейс, системный диалог выбора файла и подготовка GPU-runtime поддерживаются только в Windows. Запуск Vite на Linux не предоставляет текущий UI.

### Системные требования

- Linux-дистрибутив с `bash`
- Python 3.10 или новее
- установленный `ffmpeg`

### 1. Клонирование репозитория

```bash
git clone https://github.com/SillWo/Video-Transcribe.git
cd Video-Transcribe
```

### 2. Создание и активация виртуального окружения Python

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установка Python-зависимостей

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Опциональная постобработка русского текста устанавливается отдельно: `pip install -r requirements-postprocess.txt`. Для неё нужны Git и Git LFS. В Windows основной `start.ps1` выполняет эту подготовку автоматически.

### 4. Запуск backend API

```bash
source .venv/bin/activate
uvicorn web_api:app --host 127.0.0.1 --port 8000 --reload
```

## Windows Packaging Pipeline

The Windows release flow is split into two branches:

- `main` contains the product source code.
- `windows_dist` contains packaging-only logic: launcher, PyInstaller spec, Inno Setup script, build scripts, workflows, and release docs.

Release builds always use:

- `source/` from an exact tagged commit in `main`
- `packaging/` from `windows_dist`

Local installer build from the current checkout:

```powershell
$iscc = .\scripts\windows\install-inno-setup.ps1

powershell -ExecutionPolicy Bypass -File .\scripts\windows\build-release.ps1 `
  -ReleaseTag v0.0.0-local `
  -SourceRef refs/heads/develop `
  -PackagingDir . `
  -RepositoryRoot . `
  -IsccPath $iscc
```

Result:

- `build/windows/installer/VideoTranscribe-Setup-0.0.0-local.exe`
- `build/windows/installer/VideoTranscribe-Setup-0.0.0-local.exe.sha256`

User machines do not need manual installation of Python, Node.js, `ffmpeg`, or `yt-dlp`. The installer bundles the runtime and starts the local service automatically after installation.

### Codex refresh notes

If `main` changes product code, do not copy application source into `windows_dist`.

- Keep `windows_dist` packaging-only.
- Update `windows_dist` only when launcher, runtime config, PyInstaller, installer, or workflow logic must follow a product change.
- Rebuild release assets from exact tagged source in `main` plus packaging files from `windows_dist`.
- Never patch `source/` during the release build.
