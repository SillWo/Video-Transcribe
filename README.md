## Описание проекта

`Video Transcribe` — это локальный сервис для преобразования речи из аудио- и видеоисточников в текст без привязки к облачному SaaS-сценарию.

Сервис поддерживает два основных типа входных данных:
- локальные файлы, загружаемые с компьютера пользователя;
- удалённые ссылки на медиаресурсы, которые может обработать `yt-dlp`.

Проект включает:
- backend API на `FastAPI`;
- локальный web UI на `React + Vite`;
- пайплайн извлечения аудио через `ffmpeg`;
- распознавание речи через `faster-whisper`;
- для русского языка опциональную постобработку текста по цепочке `faster-whisper -> восстановление пунктуации -> финальная шлифовка предложений`.

Для legacy API/CLI-сценариев доступна отдельная предварительная проверка удалённого источника: она показывает, поддерживается ли ссылка и пригоден ли источник для извлечения аудио. Новый упрощённый UI запускает расшифровку напрямую.

## Новый интерфейс

Основной интерфейс работает в локальном настольном окне Electron. Для URL вставьте ссылку; для локальных файлов нажмите **«Добавить файлы»**, проверьте список имён и нажмите **«Добавить в очередь»**. Настольное приложение также принимает перетаскивание файлов; в обычном браузере нужно воспользоваться кнопкой, перетаскивание там недоступно. Выбор выполняется системным окном Windows, локальные пути передаются обработчику без копирования медиа. Для AMD Radeon 780M и других поддерживаемых графических устройств пункт **«Видеокарта»** доступен, когда графический runtime готов; иначе интерфейс предлагает использовать процессор. Кнопка закрытия прячет окно в трей, а пункт **«Выход»** позволяет штатно завершить приложение.

Профили соответствуют моделям: **«Качество» — Qwen3-ASR-1.7B F16**, **«Баланс» — Parakeet-TDT-0.6B-v3 FP32**, **«Экономный» — прежний Whisper `small`**. Для двух новых моделей не предлагаются Q8/Q4 варианты; Nemotron-3-Diarization сохраняет прежнюю GGUF Q8_0 модель, а Whisper `small` на CPU — прежний `int8` режим. Новые профили доступны на Windows: Parakeet использует `onnx-asr` на CPU, CUDA или DirectML; Qwen использует `transcribe.cpp` 0.4.1 на CPU, CUDA или Vulkan. Обычный запуск готовит необходимые окружения; выбранная модель проверяется и при необходимости подготавливается при первом задании. `start.ps1 -SetupOnly` заранее готовит оба новых профиля и оставляет Forced Aligner для Qwen, а также готовит русскую постобработку. Parakeet использует собственные временные метки слов из TDT. Для загрузки нужны сеть и место в `.runtime` проекта. Подробности и границы аппаратной проверки приведены в [описании профилей](docs/asr-presets.md).

После завершения текст можно редактировать прямо в большом поле результата. Изменения сохраняются на компьютере; также доступны копирование текста и загрузка TXT или MD. Страница **«История»** показывает прошлые задачи, дату, статус и ссылки на файлы. Текст расшифровки хранится локально в проекте: файлы находятся в `.runtime/transcriptions/`, индекс — в `.runtime/history.sqlite3`. Удаление записи удаляет её файлы результата; исходный выбранный пользователем медиафайл не затрагивается.

В настройках доступна отдельная необязательная диаризация **Nemotron-3**: по умолчанию она выключена, поддерживается до восьми говорящих. Её устройство выбирается независимо от ASR-профиля: автоматически, CPU или конкретный обнаруженный GPU. Parakeet использует native временные метки слов; для Qwen слова выравнивает отдельный Forced Aligner. Неизвестные границы остаются неизвестными, а native временные метки не обещают абсолютной точности. Формат результатов, языковые ограничения, подготовка компонентов и границы проверки описаны в [документации по диаризации](docs/diarization.md).

Desktop host обслуживает один backend на проектный runtime. При выходе активная задача штатно прерывается, ожидающие остаются в очереди. Закрытие окна оставляет приложение и очередь работающими в трее.

Один выбранный файл создаёт одну задачу; повторяющиеся пути можно добавить повторно как отдельные задачи. Все файлы, отправленные одним нажатием **«Добавить в очередь»**, получают одинаковые настройки профиля, устройства, потоков CPU и пунктуации на момент добавления. Ошибочную, отменённую или прерванную задачу можно повторить: новая задача получает источник и настройки исходной записи. Рабочее пространство может содержать несколько вкладок задач; навигационная вкладка **«История»** хранит все задачи независимо от того, закрыты ли их вкладки в рабочем пространстве.

Расширенные команды и старые CLI-инструкции проекта остаются доступны и не требуют использования нового интерфейса.

На AMD Radeon 780M / Ryzen 7 8845H с 32 ГБ RAM изолированно проверены CPU и GPU пути обеих новых моделей; несколько полных сценариев Qwen прошли с диаризацией. Эти единичные прогоны не являются обещанием скорости или широкой оценкой качества; физические NVIDIA и Intel GPU не проверялись. Условия, метрики и оставшиеся ограничения перечислены в [отчёте по профилям](docs/asr-presets.md).

## Описание функционала

- Расшифровка локальных аудио- и видеофайлов.
- Расшифровка удалённых медиаисточников по URL через `yt-dlp`.
- Для legacy API/CLI доступна отдельная проверка ссылки перед транскрибацией.
- В новом интерфейсе доступны результаты `txt` и `md`, редактирование и история задач.
- Интерфейс показывает этапы обработки, включая разделение по говорящим для включённых задач, текущую длительность и доступный от backend прогресс. Если процент неизвестен, показывается неопределённый индикатор; оценка оставшегося времени не рассчитывается. При ошибке или прерывании пользователь может повторить задачу; новая запись получает источник и настройки исходной задачи.
- Активную задачу можно отменить из панели прогресса; интерфейс отображает подтверждённый статус отмены и оставляет исходный файл и кэш моделей нетронутыми.
- Поддерживаются CPU и доступное системное GPU-устройство.
- Опциональное сохранение промежуточного извлечённого аудио.
- UI включает восстановление русской пунктуации по умолчанию; в legacy CLI post-processing можно включить отдельно через `kontur-ai/sbert_punc_case_ru` и `razdel`.

## Пример пользовательского сценария при работе с удалёнными ссылками

1. Откройте вкладку **«Транскрибация»** и вставьте URL видео.
2. Выберите профиль и устройство; для обычного случая можно оставить значения по умолчанию.
3. Нажмите **«Добавить в очередь»** и дождитесь статуса **«Готово»**.
4. При необходимости отредактируйте текст; изменения сохраняются автоматически.
5. Скопируйте результат или скачайте TXT/MD. Предыдущие задачи доступны во вкладке **«История»**.

## Пример пользовательского сценария при работе с локальным файлом

1. Откройте вкладку **«Транскрибация»** и выберите **«С компьютера»**.
2. Нажмите **«Добавить файлы»**: откроется системное окно Windows. Выберите один или несколько файлов; их имена появятся в списке перед отправкой.
3. Укажите профиль и устройство, при необходимости удалите отдельные строки из списка, затем нажмите **«Добавить в очередь»**. Все файлы в этой порции получат одинаковые настройки.
4. Отредактируйте распознанный текст и скачайте его в TXT или MD. Исходный файл на компьютере не изменяется.

## Гайд на установку под Windows

### Первый запуск

1. Установите Git, клонируйте репозиторий и откройте его папку в Проводнике.
2. Откройте PowerShell в папке проекта и запустите `.\start.ps1`. При необходимости скрипт установит Python 3.12, Git и Git LFS через `winget` для текущего пользователя, создаст `.venv`, поставит основные пакеты, соберёт production UI, установит Electron 45.2.3 и подготовит локальные GPU-runtime в `.runtime`. Веса выбранного профиля и пунктуации приложение загрузит при первом задании. Для предварительной загрузки всех моделей и пунктуации используйте `start.ps1 -SetupOnly`.
3. Откроется окно Video Transcribe; backend слушает локальный адрес `127.0.0.1:8000`.

Если политика PowerShell блокирует запуск локального файла, используйте одноразовый вызов, который не меняет системную политику:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

Установка выполняется без прав администратора и не меняет системный PATH. Node.js 22 LTS загружается из официального архива с проверкой SHA-256; Electron закреплён на версии 45.2.3. Кэш Electron, npm, профиль приложения и данные пользователя хранятся внутри `.runtime` проекта. `ffmpeg` и `ffprobe` устанавливаются через пакет `Gyan.FFmpeg.Shared`; если `winget` недоступен, поставьте Python 3.12+, Node.js 22.12+ и FFmpeg вручную для desktop-запуска (Node.js 20.19+ подходит только для headless проверки UI) и убедитесь, что `python`, `node`, `npm`, `ffmpeg` и `ffprobe` доступны текущему пользователю. Перезапустите `.\start.ps1` после ручной установки.

Кэш Python-пакетов, временные файлы и модели для этого запуска направляются в `.runtime` внутри папки проекта. Поэтому скачанные модели остаются на том же диске, где расположен проект; прежние пользовательские кэши скрипт не переносит и не удаляет.

Полезные команды из терминала в папке проекта:

```powershell
.\start.ps1 -CheckOnly       # проверить обычный запуск без установки и загрузки моделей
.\start.ps1 -CheckOnly -SetupOnly # проверить также наличие всех моделей и весов пунктуации
.\start.ps1 -SetupOnly       # подготовить зависимости, все модели и интерфейс без запуска
.\start.ps1 -SkipPostprocess # пропустить установку пакетов и весов русской пунктуации
.\start.ps1 -InstallPostprocess # явно включить русскую постобработку (это значение по умолчанию)
.\start.ps1 -NoBrowser      # запустить backend без desktop-окна
.\start.ps1 -Stop            # остановить только backend, запущенный этим проектом
```

Пакеты русской постобработки устанавливаются при подготовке проекта из `requirements-postprocess.txt`; её веса загружаются автоматически при первом задании с включённой пунктуацией или заранее командой `start.ps1 -SetupOnly`. Скрипт ставит Git и Git LFS, если они отсутствуют. Если Git или Git LFS нельзя установить через `winget`, поставьте их для текущего пользователя вручную. Логи запуска backend находятся в `.runtime\logs`. Кнопка закрытия скрывает приложение в трее; повторный запуск показывает существующее окно. Команда `-Stop` штатно останавливает активную задачу и сохраняет ожидающие задачи.

Для новых ASR-профилей GPU инициализируется по точному backend модели: Parakeet использует CUDA или DirectML; Qwen — CUDA или Vulkan. Физическое устройство, веса модели, runtime и драйвер проверяются отдельно; первое задание готовит профиль и запускает smoke-check. Если явно запрошенный GPU ASR не проходит проверку или инференс, задача завершается с ошибкой и не повторяет распознавание на CPU. Подготовительные и вспомогательные этапы могут использовать CPU с указанием причины в журнале. Для Nemotron явный GPU-выбор строгий; автоматический выбор может повторить только ошибку GPU диаризации на CPU. Системный драйвер устанавливает пользователь. Linux остаётся legacy-сценарием для старого Whisper backend/CLI без новых GPU-возможностей.

## Legacy: backend/CLI под Linux

Этот раздел описывает только старый backend/CLI-сценарий. Новый упрощённый интерфейс, системный диалог выбора файла и подготовка GPU-runtime поддерживаются только в Windows. Запуск Vite на Linux не предоставляет текущий UI.

### Системные требования

- Linux-дистрибутив с `bash`
- Python 3.10 или новее
- установленный `ffmpeg`

### 1. Клонирование репозитория

```bash
git clone https://github.com/SillWo/Video-Transcribe.git
cd Video-Transcribe
```

### 2. Создание и активация виртуального окружения Python

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установка Python-зависимостей

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

Опциональная постобработка русского текста устанавливается отдельно: `pip install -r requirements-postprocess.txt`. Для неё нужны Git и Git LFS. В Windows основной `start.ps1` выполняет эту подготовку автоматически.

### 4. Запуск backend API

```bash
source .venv/bin/activate
uvicorn web_api:app --host 127.0.0.1 --port 8000 --reload
```

## Windows Packaging Pipeline

The Windows release flow is split into two branches:

- `main` contains the product source code.
- `windows_dist` contains packaging-only logic: launcher, PyInstaller spec, Inno Setup script, build scripts, workflows, and release docs.

Release builds always use:

- `source/` from an exact tagged commit in `main`
- `packaging/` from `windows_dist`

Local installer build from the current checkout:

```powershell
$iscc = .\scripts\windows\install-inno-setup.ps1

powershell -ExecutionPolicy Bypass -File .\scripts\windows\build-release.ps1 `
  -ReleaseTag v0.0.0-local `
  -SourceRef refs/heads/develop `
  -PackagingDir . `
  -RepositoryRoot . `
  -IsccPath $iscc
```

Result:

- `build/windows/installer/VideoTranscribe-Setup-0.0.0-local.exe`
- `build/windows/installer/VideoTranscribe-Setup-0.0.0-local.exe.sha256`

User machines do not need manual installation of Python, Node.js, `ffmpeg`, or `yt-dlp`. The installer bundles the runtime and starts the local service automatically after installation.

### Codex refresh notes

If `main` changes product code, do not copy application source into `windows_dist`.

- Keep `windows_dist` packaging-only.
- Update `windows_dist` only when launcher, runtime config, PyInstaller, installer, or workflow logic must follow a product change.
- Rebuild release assets from exact tagged source in `main` plus packaging files from `windows_dist`.
- Never patch `source/` during the release build.
